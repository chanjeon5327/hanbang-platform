## 3. 구조적 리스크

| 리스크 | 설명 |
|--------|------|
| **orders.product_id FK** | products(id) 참조 → content_items.id와 products.id 불일치 시 주문 실패 |
| **v_join_to_buy_7d** | o.content_id 참조하나 orders에 content_id 컬럼 없음 → 뷰 오류 가능 |
| **이중 ID 공간** | content_items(마켓/추천) vs products(주문) 분리로 매핑 복잡 |
| **product_chat_messages** | product_id 컬럼명이나 content_id 의미로 사용, FK 없음 |

## 4. 이행 목표

- **마켓 기준 ID**: content_items.id (UUID) 단일화
- **orders**: content_id 추가, product_id 듀얼 유지 (nullable)
- **products**: content_id NOT NULL 추가, 판매/정산 설정 전용
- **API**: 내부 변수 productId → contentId, body product_id / content_id 모두 수용
